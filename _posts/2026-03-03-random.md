Reinforcement learning (RL) is a framework for sequential decision-making in which an agent interacts with an environment to maximise cumulative reward. Unlike supervised learning, the agent does not receive labelled “correct” actions. Instead, it must discover a policy through trial-and-error interaction.

This paradigm gained widespread attention when DeepMind’s AlphaGo defeated the world champion at Go, demonstrating that reinforcement learning combined with deep neural networks can master complex strategic environments. I highly recommend everyone watches the documentary on the AlphaGo team, which you can find [here](https://www.youtube.com/watch?v=WXuK6gekU1Y).

In this post, we review the core theoretical ingredients of RL and then apply them to build a Connect-4 solver.

# **Quick RL Overview**

This section is a compact refresher on the main RL concepts. For a detailed explanation of RL, I cannot recommend enough the book called [Reinforcement Learning: An Introduction](https://www.andrew.cmu.edu/course/10-703/textbook/BartoSutton.pdf) by Sutton and Barto for classical RL, and the OpenAI course [Spinning Up in Deep RL](https://spinningup.openai.com/en/latest/) for deep learning RL methods.

## **States, Actions and Policies**

At the heart of RL is the interaction loop:

1. The agent observes a **state** $$ s_t $$
2. It selects an **action** $$ a_t $$
3. The environment returns a **reward** $$ r_{t+1} $$ and next state $$ s_{t+1} $$
4. The cycle then repeats forever, or until some final state has been reached. 

This is summarised in the schematic below:

Formally:

- **State space**: $$ \mathcal{S} $$, is the set of all possible states.
- **Action space**: $$ \mathcal{A} $$, is the set of possible actions. The set of possible actions might be conditioned on the state itself. 
- **Reward space**: $$ \mathcal{R} $$, is the set of all possible rewards.
- **Policy**: $$ \pi(a\vert s) $$, a mapping from states to action probabilities.

A canonical toy example is the *k-armed bandit*. There is a single state and $$ k $$ actions. Each action produces a reward sampled from an unknown distribution:

$$
a \sim \pi(a), \quad r \sim \mathcal{R}_a
$$

For example, the image below shows a 10-armed bandit, with the distributions for each of the 10 actions.

If we knew the true expected reward $$ \mathbb{E}[r\vert a] $$, the optimal policy would always select:

$$
a^* = \arg\max_a \mathbb{E}[r|a]
$$

But, since the reward distributions are generally unknown, the agent must balance:

- **Exploration** — trying uncertain actions  
- **Exploitation** — selecting the currently best-known action  

Now extend this idea to multiple states. Suppose we have two bandits, $$ s_1 $$ and $$ s_2 $$, each with different reward distributions. The optimal action now depends on the state:

$$
\pi(a|s)
$$

This state-dependence is what distinguishes reinforcement learning from bandit problems.


## **Reward and Action-Values**

In sequential environments, immediate reward is insufficient, because an action may maximise the immediate reward but lead to less reward later on. We instead optimise **expected return**:

$$
G_t = r_{t+1} + \gamma r_{t+2} + ... = \sum_{k=0}^{\infty} \gamma^k r_{t+k+1},
$$

where $$ \gamma \in [0,1] $$ is the discount factor. There are a few reasons for including this. First, for problems that can go on forever, including a discount factor is mathematically convenient as it keeps the expected return non-infinite. It also encapsulates uncertainty of how the current state affects the next state: we are more uncertainty about the far future than we are the immediate future. 



Using the expected return, we can define the **state-value function** of a state $$ s $$ which is the expected return from that state when following the policy $$ \pi $$: 

$$
V^\pi(s) = \mathbb{E}_\pi[G_t \mid s_t = s]
$$

and the **action-value function** as the expected return when starting at a state $$ s $$, taking an action $$ a $$, then following the policy $$ \pi $$:

$$
Q^\pi(s,a) = \mathbb{E}_\pi[G_t \mid s_t = s, a_t = a],
$$

which are related using the policy: 

$$
V^\pi(s) = \sum_{a} \pi(a \vert s) Q^\pi(s,a)
$$

Given this, we can define the optimal policy as the policy that maximises the value functions:

$$
V^*(s) = \max_\pi V^\pi(s) \quad ; \quad Q^*(s,a) = \max_\pi Q^\pi(s,a)
$$

The optimal policy is then:

$$
\pi^*(s) = \arg\max_a Q^*(s,a),
$$

i.e. it is the policy which, for a state $$ s $$, picks the action with the highest expected reward. 
Thus, learning optimal behaviour reduces to estimating $$ Q^*(s,a) $$.

## **Markov Decision Process**

Most RL problems are formalised as a **Markov Decision Process (MDP)**:

$$
(\mathcal{S}, \mathcal{A}, P, R, \gamma)
$$

where:

- $$ \mathcal{S} $$ is the state space
- $$ \mathcal{A} $$ is the action space
- $$ P $$ defines the transition dynamics
- $$ R $$ is the reward function
- $$ \gamma \in [0,1] $$ is the discount factor

The system satisfies the **Markov property**:

$$
P(s_{t+1} \mid s_t, a_t, s_{t-1}, \dots) = P(s_{t+1} \mid s_t, a_t)
$$

That is, the distribution over future states depends only on the current state and action, not the full history of the system.

As seen in the bandit example, the reward obtained after taking an action may be stochastic. More generally, both the reward and the next state may be random. To capture this, we define the **joint transition probability**

$$
p(s', r' \mid s, a)
$$

which represents the probability of transitioning from state $$ s $$ to state $$ s' $$ and receiving reward $$ r' $$ after taking action $$ a $$.

This defines a valid probability distribution:

$$
\sum_{s' \in \mathcal{S}} \sum_{r' \in \mathcal{R}} p(s', r' \mid s, a) = 1
$$

If we are only interested in the probability of transitioning to a particular next state regardless of reward, we marginalise over the reward:

$$
p(s' \mid s, a) =
\sum_{r' \in \mathcal{R}} p(s', r' \mid s, a)
$$

Connect-4 satisfies the Markov property: the full board configuration completely determines the set of possible next states and rewards.

## **Bellman Equations**

The Bellman equations express value functions recursively. The key observation is that the return from a state can be decomposed into the immediate reward plus the discounted return from the next timestep.

Starting with the **state-value function** under a policy $$\pi$$, the expected return starting from state $$s$$ is:

$$
\begin{aligned}
V^\pi(s) &= \mathbb{E}_\pi[G_t \mid S_t = s] \\
         &= \mathbb{E}_\pi[r_{t+1} + \gamma r_{t+2} + \gamma^2 r_{t+3} + \dots \mid S_t = s] \\
         &= \mathbb{E}_\pi[r_{t+1} + \gamma (r_{t+2} + \gamma r_{t+3} + \dots) \mid S_t = s] \\
         &= \mathbb{E}_\pi[r_{t+1} + \gamma G_{t+1} \mid S_t = s] \\
         &= \mathbb{E}_\pi[r_{t+1} + \gamma V^\pi(s') \mid S_t = s], \\
\end{aligned}
$$

where we have used the fact that $$ \mathbb{E}_\pi[G_{t+1} \mid S_t = s] = \mathbb{E}_\pi[V^\pi(s') \mid S_t = s]  $$ which follows from the Markov property. 

We can perform the same process with the action-value function: 


$$
\begin{aligned}
Q^\pi(s, a) &= \mathbb{E}_\pi[G_t \mid S_t = s, A_t = a] \\
         &= \mathbb{E}_\pi[r_{t+1} + \gamma r_{t+2} + \gamma^2 r_{t+3} + \dots \mid S_t = s, A_t = a] \\
         &= \mathbb{E}_\pi[r_{t+1} + \gamma (r_{t+2} + \gamma r_{t+3} + \dots) \mid S_t = s, A_t = a] \\
         &= \mathbb{E}_\pi[r_{t+1} + \gamma G_{t+1} \mid S_t = s, A_t = a] \\
         &= \mathbb{E}_\pi[r_{t+1} + \gamma Q^\pi(s', a') \mid S_t = s, A_t = a] \\
\end{aligned}
$$

Expanding the expectation over actions and next states yields the **Bellman expectation equations**:

$$
V^\pi(s) =
\sum_a \pi(a|s)
\sum_{s'} P(s'|s,a)
\left[
R(s,a) + \gamma V^\pi(s')
\right].
$$

$$
Q^\pi(s,a) =
\sum_{s'} P(s'|s,a)
\left[
R(s,a) + \gamma \sum_{a'} \pi(a'|s')\, Q^\pi(s',a')
\right].
$$

---

### **Optimal Value Function**

The **optimal value function** is defined as

$$
V^*(s) = \max_\pi V^\pi(s).
$$

Under an optimal policy the agent always selects the action with the highest expected return, giving the **Bellman optimality equations**:

$$
V^*(s) =
\max_a
\sum_{s'} P(s'|s,a)
\left[
R(s,a) + \gamma V^*(s')
\right].
$$

$$
Q^*(s,a) =
\sum_{s'} P(s'|s,a)
\left[
R(s,a) + \gamma \max_{a'} Q^*(s',a')
\right].
$$

These equations define a **fixed-point problem**: the optimal value function is the solution to the Bellman optimality equation. Iterative algorithms such as value iteration or Q-learning converge to this solution under suitable conditions.

## **Learning** $$ \boldsymbol{Q^*(s,a)} $$

From the previous section, we saw that once we know the optimal action-value function $$Q^*(s,a)$$, the optimal policy is simply

$$
\pi^*(s) = \arg\max_a Q^*(s,a).
$$

In practice, however, we do not know $$Q^*$$. Computing it exactly is generally intractable because the number of possible states grows exponentially with the length of the game. Even for a relatively small game such as Connect-4, enumerating all possible game states is prohibitively expensive.

Instead, we approximate the action-value function. Modern reinforcement learning methods rely on the fact that **neural networks are universal function approximators**, allowing us to learn a parameterised estimate of $$Q(s,a)$$ directly from experience. This approach is known as **Deep Q-Learning**.

---

### Q-Learning Update

Starting from the Bellman optimality equation,

$$
Q^*(s,a) =
\sum_{s'} P(s'|s,a)
\left[
R(s,a) + \gamma \max_{a'} Q^*(s',a')
\right],
$$

we observe that the optimal action-value function satisfies a recursive relationship. Generally, however, we do not have the transition probabilities $$ P(s'\vert s,a) $$ so we can't directly calculate the right hand side of the equatiuon. Instead, we can form an estimate of it using many transitions, with each transition being:

$$
(s_t, a_t, r_{t+1}, s_{t+1}),
$$

and using these to calculate

$$
r_{t+1} + \gamma \max_{a'} Q(s_{t+1}, a').
$$

Averaging over all these estimates approaches the optimal value, $$ Q^*(s,a) $$. This can be seen with the simple example: if we define $v_i = R(s,a) + \gamma \max_{a'} Q^*(s_i,a')$, and we have the transition probabilities: 

| Next state | Transition Probability | Value |
|------------|-------------|-------|
| $s_1$      | 0.2         | $v_1$ |
| $s_2$      | 0.8         | $v_2$ |

Then the Bellman equation is

$$
Q^*(s,a) = 0.2 v_1 + 0.8 v_2.
$$

If we then sampled transitions, we would find that $$ s_1 $$ would appear $$ \approx 20$$% of the time, and $$ s_2 $$ would appear $$ \approx 80$$% of the time. So if we averaged over a whole sequence of transitions e.g. ($v_1, v_2, v_2, v_2, v_1...$), the empiracal mean would approach $$ Q^*(s,a) = 0.2 v_1 + 0.8 v_2$$. In other words, as the Bellman equation involves a an expectation over states, a single sample drawn from the environment is therefore a **Monte Carlo sample**  from this distribution. 

If we are using a neural network to estimate $$Q(s_t,a_t)$$ the Bellman equation will not initially hold, and $Q(s_t,a_t)$ will not equal $$r + \gamma \max_{a'} Q(s_{t+1},a')$$. The difference between these two values is called the **temporal-difference (TD) error**:

$$
r_{t+1}
+
\gamma \max_{a'} Q(s_{t+1},a')
-
Q(s_t,a_t).
$$

We train the network by minimising the squared TD error. Given a transition $$(s,a,r,s')$$ the loss function is

$$
\mathcal{L}(\theta) =
\left(
r + \gamma \max_{a'} Q_{\theta^-}(s',a')
-
Q_\theta(s,a)
\right)^2.
$$


NOTE: Here $$\theta^-$$ denotes the parameters of a **target network**, which are periodically updated from the main network.

---

### Training Tricks

Naively applying Q-learning with neural networks can lead to unstable training and oscillations. Two techniques are commonly used to address this.

**Experience Replay**

Instead of training on consecutive transitions, we store transitions in a replay buffer and sample them randomly during training. This breaks correlations between neighbouring samples and improves stability.

**Target Networks**

We maintain two networks:

- a **policy network** $$Q_\theta$$ that is updated every training step  
- a **target network** $$Q_{\theta^-}$$ used to compute the TD target

The target network parameters are periodically copied from the policy network. Because the target changes slowly, this significantly reduces training oscillations. The loss function would then become

$$
\mathcal{L}(\theta) =
\left(
r + \gamma \max_{a'} Q_{\theta^-}(s',a')
-
Q_\theta(s,a)
\right)^2.
$$

where  $$\theta^-$$ denotes the parameters of a **target network**, which are periodically updated from the main network.

**Exploitation vs Exploration**

When training the model, we want to ensure that the model experiences many different states from which it can learn from. However, when running the simulated games, if we constantly picked the move corresponding to $$ \max_{a} Q_{\theta^-}(s,a) $$ then the model might only see a small subset of the possible states. On the other hand, we don't want every action to be chosen randomly, as we want the model to play optimally.  This is known as the exploitation vs exploration problem. To overcome this, the action is chosen using the $$ \varepsilon$$-greedy method. With this, we pick an initial value of $$ \varepsilon \in (0, 1)$$ and fraction $$ \varepsilon  $$ of the time we pick an action following $$ \max_{a} Q_{\theta^-}(s,a) $$, whilst for the rest we pick an action randomly. During training we then reduce the value of $$ \varepsilon $$.

# Implementing the Connect-4 Environment

We begin by implementing the game environment. The environment stores
the board state, applies moves, and determines when the game has ended.

The full implementation of the `Connect4` class is shown below.

``` python
import numpy as np

class Connect4:

    def __init__(self):
        self.height = 6
        self.width = 7
        self.board_state = np.zeros((self.height, self.width), dtype=np.int8)
        self.players = {1: 1, 2: 2}
        self.gameOver = False
        self.reward = {'win': 1, 'draw': -1, 'lose': -1}

    def get_allowed_moves(self):
        available_cols = []
        for j in range(self.width):
            col = self.board_state[:, j]
            if 0 in col:
                available_cols.append(j)
        return available_cols

    def make_move(self, m, player):

        if m in self.get_allowed_moves():

            col = self.board_state[:, m]

            open_slot = np.argmax(col != 0) - 1

            self.board_state[open_slot, m] = self.players[player]

        reward = self.check_game_done(player)

        return self.board_state.copy(), reward

    def checkHas4InARow(self, arr, player):

        current_val = arr[0]
        current_count = 1

        longest_val = arr[0]
        longest_count = 1

        for val in arr[1:]:

            if val == current_val:
                current_count += 1
            else:
                current_val = val
                current_count = 1

            if current_count > longest_count:
                longest_count = current_count
                longest_val = current_val

        if (longest_val == player) and (longest_count >= 4):
            return True

        return False

    def reset(self):
        self.__init__()
```

## Explanation

The environment stores the Connect-4 board as a **6×7 NumPy array**:

  Value   Meaning
  ------- ---------------------
  0       empty cell
  1       player 1 (RL agent)
  2       player 2

The main responsibilities of the environment are:

### Initialisation (`__init__`)

This creates an empty board and stores metadata about the game such as
the board dimensions and player identifiers.

### Valid move detection (`get_allowed_moves`)

This function returns a list of columns that still contain empty cells.
The agent must choose actions from this set to avoid illegal moves.

### Applying moves (`make_move`)

When a player selects a column, the piece falls to the **lowest
available slot** in that column. After placing the piece, the
environment checks whether the game has ended and returns:

-   the updated board state\
-   the reward associated with the move

### Win detection (`checkHas4InARow`)

This helper function checks whether a sequence contains **four
consecutive pieces from the same player**. It is used internally when
scanning rows, columns, and diagonals to detect wins.

### Resetting the environment (`reset`)

At the start of each training episode the board must be cleared. The
`reset` function simply reinitialises the environment.

This environment class provides everything the reinforcement learning
agent needs in order to interact with the game.

# Experience Replay

Instead of learning from consecutive transitions, we store transitions
in a **replay buffer** and sample randomly.

A transition stores:

-   state
-   action
-   reward
-   next state
-   done flag

``` python
from collections import deque
import random

class ReplayBuffer:

    def __init__(self, capacity):
        self.memory = deque(maxlen=capacity)

    def push(self, transition):
        self.memory.append(transition)

    def sample(self, batch_size):
        return random.sample(self.memory, batch_size)

    def __len__(self):
        return len(self.memory)
```

Random sampling breaks correlations between sequential game states and
stabilises training.

## Q-Network (TransformerDQN)

Rather than using a flattened feed‑forward network, this implementation
uses a **Transformer‑based Q-network** that treats the Connect‑4 board
as a sequence of tokens.

Each board cell has a categorical value:

  Value   Meaning
  ------- ------------
  0       empty cell
  1       player 1
  2       player 2

These values are first embedded into vectors using a learned embedding
layer:

``` python
self.cell_embed = nn.Embedding(3, d_model)
```

Because the board is a **2D grid**, the model also adds learned **row
and column positional embeddings** so the network knows where each token
is located:

``` python
self.row_embed = nn.Embedding(self.n_rows, d_model)
self.col_embed = nn.Embedding(self.n_cols, d_model)

pos = self.row_embed(rows) + self.col_embed(cols)
x = x + pos.unsqueeze(0)
```

The board is then flattened into a sequence of tokens (one per cell),
and a learned **CLS token** is added to represent a global summary of
the board:

``` python
x = x.view(B, self.seq_len, self.d_model)

cls = self.cls.expand(B, -1, -1)
x = torch.cat([cls, x], dim=1)
```

This sequence is passed through several **Transformer encoder layers**
containing multi‑head self‑attention and feed‑forward networks:

``` python
self.layers = nn.ModuleList(
    [TransformerEncoderLayer(d_model, num_heads, d_ff, dropout, relpos_bias=self.relpos_bias)
     for _ in range(num_layers)]
)
```

Self‑attention allows the model to learn relationships between board
positions, such as:

-   horizontal threats
-   vertical stacks
-   diagonal connect‑4 patterns

The network also includes a learned **2D relative position bias** that
helps the attention mechanism encode spatial relationships between board
cells.

After the Transformer layers, the representation of the CLS token is
used to produce **Q-values for each column action**:

``` python
h = x[:, 0, :]
logits = self.policy_head(h)
```

Since some columns may already be full, the model applies **action
masking** so that illegal moves cannot be selected:

``` python
masked_logits = logits.masked_fill(~valid_action_mask, -1e9)
```

The final output therefore contains:

-   `logits` -- raw Q-values for each column
-   `masked_logits` -- Q-values with invalid actions suppressed
-   `valid_action_mask` -- which actions are legal

During action selection, the agent simply chooses the column with the
highest masked Q-value:

``` python
action = torch.argmax(masked_logits[0]).item()
```

Using a Transformer allows the model to capture **long‑range spatial
dependencies** on the board more effectively than a flattened MLP, which
is particularly useful for detecting diagonal and multi‑step connect‑4
threats.

# ε‑Greedy Exploration

To balance exploration and exploitation, we use an **ε‑greedy policy**.

-   With probability **ε** choose a random action
-   Otherwise choose the action with the highest Q‑value

``` python
def select_action(state, epsilon):

    if random.random() < epsilon:
        return random.choice(env.get_allowed_moves())

    state_tensor = torch.tensor(state.flatten(), dtype=torch.float32)

    with torch.no_grad():
        q_values = policy_net(state_tensor)

    return torch.argmax(q_values).item()
```

Exploration is important early in training so the agent can discover
strong strategies.

------------------------------------------------------------------------

# Q‑Learning Update

During training we update the network using the Q‑learning target

$$
y = r + \gamma \max_{a'} Q(s',a').
$$

The network is trained to minimise

$$
(Q(s,a) - y)^2.
$$

Example training step:

``` python
def optimise_model():

    if len(memory) < batch_size:
        return

    transitions = memory.sample(batch_size)

    states, actions, rewards, next_states = zip(*transitions)

    states = torch.tensor(states, dtype=torch.float32)
    actions = torch.tensor(actions)
    rewards = torch.tensor(rewards)

    q_values = policy_net(states)
    state_action_values = q_values.gather(1, actions.unsqueeze(1))

    next_q_values = target_net(next_states).max(1)[0].detach()

    expected_q_values = rewards + gamma * next_q_values

    loss = nn.MSELoss()(state_action_values.squeeze(), expected_q_values)

    optimizer.zero_grad()
    loss.backward()
    optimizer.step()
```

------------------------------------------------------------------------

# Training Loop

Finally we combine all components into the training loop.

``` python
for episode in range(num_episodes):

    state = env.reset()

    done = False

    while not done:

        action = select_action(state, epsilon)

        next_state, reward = env.make_move(action, 1)

        memory.push((state, action, reward, next_state))

        state = next_state

        optimise_model()
```

Over many episodes the Q‑network gradually learns which moves lead to
winning positions.

# The Reinforcement Learning Pipeline

Now that we have introduced all the components, we can describe the **full RL training pipeline** used to train the Connect-4 agent.

At a high level, the process looks like this:

1. Initialise the environment and neural networks.
2. Play games against the random opponent.
3. Store transitions in the replay buffer.
4. Sample random batches from the replay buffer.
5. Update the Q-network using the Bellman target.
6. Periodically update the target network.
7. Repeat for many episodes.

This loop gradually improves the policy.
