Reinforcement learning (RL) is a framework for sequential decision-making in which an agent interacts with an environment to maximise cumulative reward. Unlike supervised learning, the agent does not receive labelled “correct” actions. Instead, it must discover a policy through trial-and-error interaction.

This paradigm gained widespread attention when DeepMind’s AlphaGo defeated the world champion at Go, demonstrating that reinforcement learning combined with deep neural networks can master complex strategic environments. I highly recommend everyone watches the documentary on the AlphaGo team, which you can find here.

In this post, we review the core theoretical ingredients of RL and then apply them to build a Connect-4 solver. The code for this can be found in the following github repo.

Quick RL Overview

This section is a compact refresher on the main RL concepts. For a detailed explanation of RL, I cannot recommend enough the book called Reinforcement Learning: An Introduction by Sutton and Barto for classical RL, and the OpenAI course Spinning Up in Deep RL for deep learning RL methods.

States, Actions and Policies

At the heart of RL is the interaction loop:

  1. The agent observes a state \(s_t\)
  2. It selects an action \(a_t\)
  3. The environment returns a reward \(r_{t+1}\) and next state \(s_{t+1}\)
  4. The cycle then repeats forever, or until some final state has been reached.

This is summarised in the schematic below:

Formally:

  • State space: \(\mathcal{S}\), is the set of all possible states.
  • Action space: \(\mathcal{A}\), is the set of possible actions. The set of possible actions might be conditioned on the state itself.
  • Reward space: \(\mathcal{R}\), is the set of all possible rewards, which also might be conditioned on the state.
  • Policy: \(\pi(a\vert s)\), a mapping from states to action probabilities.

A canonical toy example is the k-armed bandit. There is a single state and \(k\) actions. Each action produces a reward sampled from an unknown distribution:

\[a \sim \pi(a), \quad r \sim \mathcal{R}_a\]

For example, the image below shows a 10-armed bandit, with the distributions for each of the 10 actions.

If we knew the true expected reward \(\mathbb{E}[r\vert a]\), the optimal policy would always select:

\[a^* = \arg\max_a \mathbb{E}[r|a]\]

But, since the reward distributions are generally unknown, the agent must balance:

  • Exploration — trying uncertain actions
  • Exploitation — selecting the currently best-known action

Now extend this idea to multiple states. Suppose we have two bandits, \(s_1\) and \(s_2\), each with different reward distributions. The optimal action now depends on the state:

\[\pi(a|s)\]

This is the general case for most RL problems, where the agent picks actions which leads to a reward, and can also lead to a new state.

Reward and Action-Values

In sequential environments, immediate reward is insufficient, because an action may maximise the immediate reward but lead to less reward later on. We instead optimise expected return:

\[G_t = r_{t+1} + \gamma r_{t+2} + ... = \sum_{k=0}^{\infty} \gamma^k r_{t+k+1},\]

where \(\gamma \in [0,1]\) is the discount factor. There are a few reasons for including this. First, for problems that can go on forever, including a discount factor is mathematically convenient as it keeps the expected return non-infinite. Second, the discount factor expresses a preference for earlier rewards over distant future rewards: there is more uncertainty about how a current state influences a state in the far future than the immediate next state.

Using the expected return, we can define the state-value function of a state \(s\) which is the expected return from that state when following the policy \(\pi\):

\[V^\pi(s) = \mathbb{E}_\pi[G_t \mid s_t = s]\]

and the action-value function as the expected return when starting at a state \(s\), taking an action \(a\), then following the policy \(\pi\):

\[Q^\pi(s,a) = \mathbb{E}_\pi[G_t \mid s_t = s, a_t = a],\]

which are related using the policy:

\[V^\pi(s) = \sum_{a} \pi(a \vert s) Q^\pi(s,a)\]

Given this, we can define the optimal policy as the policy that maximises the value functions:

\[V^*(s) = \max_\pi V^\pi(s) \quad ; \quad Q^*(s,a) = \max_\pi Q^\pi(s,a)\]

The optimal policy is then:

\[\pi^*(s) = \arg\max_a Q^*(s,a),\]

i.e. it is the policy which, for a state \(s\), picks the action with the highest expected reward. Thus, learning optimal behaviour reduces to estimating \(Q^*(s,a)\).

Markov Decision Process

Most RL problems are formalised as a Markov Decision Process (MDP):

\[(\mathcal{S}, \mathcal{A}, P, R, \gamma)\]

where:

  • \(\mathcal{S}\) is the state space
  • \(\mathcal{A}\) is the action space
  • \(P\) defines the transition dynamics
  • \(R\) is the reward function
  • \(\gamma \in [0,1]\) is the discount factor

The system satisfies the Markov property:

\[P(s_{t+1} \mid s_t, a_t, s_{t-1}, \dots) = P(s_{t+1} \mid s_t, a_t)\]

That is, the distribution over future states depends only on the current state and action, not the full history of the system.

As seen in the bandit example, the reward obtained after taking an action may be stochastic. More generally, both the reward and the next state may be random. To capture this, we define the joint transition probability

\[p(s', r' \mid s, a)\]

which represents the probability of transitioning from state \(s\) to state \(s'\) and receiving reward \(r'\) after taking action \(a\).

This defines a valid probability distribution:

\[\sum_{s' \in \mathcal{S}} \sum_{r' \in \mathcal{R}} p(s', r' \mid s, a) = 1\]

If we are only interested in the probability of transitioning to a particular next state regardless of reward, we marginalise over the reward:

\[p(s' \mid s, a) = \sum_{r' \in \mathcal{R}} p(s', r' \mid s, a)\]

Connect-4 satisfies the Markov property: the full board configuration completely determines the set of possible next states and rewards.

Bellman Equations

The Bellman equations express value functions recursively. The key observation is that the return from a state can be decomposed into the immediate reward plus the discounted return from the next timestep.

Starting with the state-value function under a policy \(\pi\), the expected return starting from state \(s\) is:

\[\begin{aligned} V^\pi(s) &= \mathbb{E}_\pi[G_t \mid S_t = s] \\ &= \mathbb{E}_\pi[r_{t+1} + \gamma r_{t+2} + \gamma^2 r_{t+3} + \dots \mid S_t = s] \\ &= \mathbb{E}_\pi[r_{t+1} + \gamma (r_{t+2} + \gamma r_{t+3} + \dots) \mid S_t = s] \\ &= \mathbb{E}_\pi[r_{t+1} + \gamma G_{t+1} \mid S_t = s] \\ &= \mathbb{E}_\pi[r_{t+1} + \gamma V^\pi(s') \mid S_t = s], \\ \end{aligned}\]

where we have used the fact that \(\mathbb{E}_\pi[G_{t+1} \mid S_t = s] = \mathbb{E}_\pi[V^\pi(s') \mid S_t = s]\) which follows from the Markov property.

We can perform the same process with the action-value function:

\[\begin{aligned} Q^\pi(s, a) &= \mathbb{E}_\pi[G_t \mid S_t = s, A_t = a] \\ &= \mathbb{E}_\pi[r_{t+1} + \gamma r_{t+2} + \gamma^2 r_{t+3} + \dots \mid S_t = s, A_t = a] \\ &= \mathbb{E}_\pi[r_{t+1} + \gamma (r_{t+2} + \gamma r_{t+3} + \dots) \mid S_t = s, A_t = a] \\ &= \mathbb{E}_\pi[r_{t+1} + \gamma G_{t+1} \mid S_t = s, A_t = a] \\ &= \mathbb{E}_\pi[r_{t+1} + \gamma Q^\pi(s', a') \mid S_t = s, A_t = a] \\ \end{aligned}\]

Expanding the expectation over actions and next states yields the Bellman expectation equations:

\[V^\pi(s) = \sum_a \pi(a|s) \sum_{s'} P(s'|s,a) \left[ R(s,a) + \gamma V^\pi(s') \right].\] \[Q^\pi(s,a) = \sum_{s'} P(s'|s,a) \left[ R(s,a) + \gamma \sum_{a'} \pi(a'|s')\, Q^\pi(s',a') \right].\]

Optimal Value Function

The optimal value function is defined as

\[V^*(s) = \max_\pi V^\pi(s).\]

Under an optimal policy the agent always selects the action with the highest expected return, giving the Bellman optimality equations:

\[V^*(s) = \max_a \sum_{s'} P(s'|s,a) \left[ R(s,a) + \gamma V^*(s') \right].\] \[Q^*(s,a) = \sum_{s'} P(s'|s,a) \left[ R(s,a) + \gamma \max_{a'} Q^*(s',a') \right].\]

These equations define a fixed-point problem: the optimal value function is the solution to the Bellman optimality equation. Iterative algorithms such as value iteration or Q-learning converge to this solution under suitable conditions.

Learning \(\boldsymbol{Q^*(s,a)}\)

From the previous section, we saw that once we know the optimal action-value function \(Q^*(s,a)\), the optimal policy is simply

\[\pi^*(s) = \arg\max_a Q^*(s,a).\]

In practice, however, we do not know \(Q^*\). Computing it exactly is generally intractable because the number of possible states grows exponentially with the length of the game. Even for a relatively small game such as Connect-4, enumerating all possible game states is prohibitively expensive.

Instead, we approximate the action-value function. Modern reinforcement learning methods rely on the fact that neural networks are universal function approximators, allowing us to learn a parameterised estimate of \(Q(s,a)\) directly from experience. This approach is known as Deep Q-Learning.

Q-Learning Update

Starting from the Bellman optimality equation,

\[Q^*(s,a) = \sum_{s'} P(s'|s,a) \left[ R(s,a) + \gamma \max_{a'} Q^*(s',a') \right],\]

we observe that the optimal action-value function satisfies a recursive relationship. Generally, however, we do not have the transition probabilities \(P(s'\vert s,a)\) so we can’t directly calculate the right hand side of the equation. Instead, we can form an estimate of it using many transitions, with each transition being:

\[(s_t, a_t, r_{t+1}, s_{t+1}),\]

and using these to calculate

\[r_{t+1} + \gamma \max_{a'} Q(s_{t+1}, a').\]

Averaging over all these estimates approaches the optimal value, \(Q^*(s,a)\). This can be seen with the simple example: if we define $v_i = R(s,a) + \gamma \max_{a’} Q^*(s_i,a’)$, and we have the transition probabilities:

Next state Transition Probability Value
$s_1$ 0.2 $v_1$
$s_2$ 0.8 $v_2$

Then the Bellman equation is

\[Q^*(s,a) = 0.2 v_1 + 0.8 v_2.\]

If we then sampled transitions, we would find that \(s_1\) would appear \(\approx 20\)% of the time, and \(s_2\) would appear \(\approx 80\)% of the time. So if we averaged over a whole sequence of transitions e.g. ($v_1, v_2, v_2, v_2, v_1…$), the empirical mean would approach \(Q^*(s,a) = 0.2 v_1 + 0.8 v_2\). In other words, as the Bellman equation involves a an expectation over states, a single sample drawn from the environment is therefore a Monte Carlo sample from this distribution.

If we are using a neural network to estimate \(Q(s_t,a_t)\) the Bellman equation will not initially hold, and $Q(s_t,a_t)$ will not equal \(r + \gamma \max_{a'} Q(s_{t+1},a')\). The difference between these two values is called the temporal-difference (TD) error:

\[r_{t+1} + \gamma \max_{a'} Q(s_{t+1},a') - Q(s_t,a_t).\]

We train the network by minimising the squared TD error. Given a transition \((s,a,r,s')\) the loss function is

\[\mathcal{L}(\theta) = \left( r + \gamma \max_{a'} Q_{\theta}(s',a') - Q_\theta(s,a) \right)^2.\]

Training Tricks

Naively applying Q-learning with neural networks can lead to unstable training and oscillations. Two techniques are commonly used to address this.

Experience Replay

Instead of training on consecutive transitions, we store transitions in a replay buffer and sample them randomly during training. This breaks correlations between neighbouring samples and improves stability.

Target Networks

We maintain two networks:

  • a policy network \(Q_\theta\) that is updated every training step
  • a target network \(Q_{\theta^-}\) used to compute the TD target

The target network parameters are periodically copied from the policy network. Because the target changes slowly, this significantly reduces training oscillations. The loss function would then become

\[\mathcal{L}(\theta) = \left( r + \gamma \max_{a'} Q_{\theta^-}(s',a') - Q_\theta(s,a) \right)^2.\]

where \(\theta^-\) denotes the parameters of a target network, which are periodically updated from the main network.

Exploitation vs Exploration

When training the model, we want to ensure that the model experiences many different states from which it can learn from. However, when running the simulated games, if we constantly picked the move corresponding to \(\max_{a} Q_{\theta^-}(s,a)\) then the model might only see a small subset of the possible states. On the other hand, we don’t want every action to be chosen randomly, as we want the model to play optimally. This is known as the exploitation vs exploration problem. To overcome this, the action is chosen using the \(\varepsilon\)-greedy method. With ε-greedy exploration we choose actions as follows:

  • with probability ε we select a random action (exploration)
  • with probability 1−ε we select the greedy action that maximises the Q-value

During training ε is gradually reduced so the policy becomes increasingly greedy as learning progresses.

RL for Connect-4

In this project the agent plays against a random opponent rather than another learning agent. This simplifies the learning problem: the environment becomes stationary and the agent only needs to learn strategies that beat random play. Despite this simplification the agent can still discover useful behaviours such as:

  • blocking opponent threats
  • building vertical stacks
  • forming diagonal connect‑4 patterns

More advanced RL systems (for example AlphaZero) instead use self-play, where two agents learn simultaneously and continually improve against each other.

Now that we have introduced the core reinforcement learning concepts, we can apply them to the game of Connect‑4.
Our goal is to train an agent that learns an approximation to the optimal action‑value function

\[Q(s,a)\]

so that it can choose actions according to

\[\pi(s) = \arg\max_a Q(s,a).\]

In this project:

  • Player 1 is the reinforcement learning agent.
  • Player 2 selects moves randomly.
  • The agent learns using Deep Q‑Learning.

Training against a random opponent does not produce a perfect solver, but it provides a clean environment for demonstrating how a Deep Q‑Network (DQN) works.

The Reinforcement Learning Pipeline

Now that we have introduced all the components, we can describe the full RL training pipeline used to train the Connect-4 agent.

At a high level, the process looks like this:

  1. Initialise the environment and neural networks.
  2. Play games against the random opponent.
  3. Store transitions in the replay buffer.
  4. Sample random batches from the replay buffer.
  5. Update the Q-network using the Bellman target.
  6. Periodically update the target network.
  7. Repeat for many episodes.

This loop gradually improves the policy.

import numpy as np

class Connect4:

    def __init__(self):
        self.height = 6 # height of board
        self.width = 7  # width of board
        # array that stores the board state
        self.board_state = np.zeros((self.height, self.width), dtype=np.int8) 
        self.players = {1: 1, 2: 2}
        # is the game over
        self.gameOver = False
        # if the game has finished, did they win, lose or draw?
        self.isWinDrawLoss = {'win': 1, 'draw': -1, 'lose': -1}

    # if there is a 0 in a column then it is an allowed moved
    def get_allowed_moves(self):
        available_cols = []
        for j in range(self.width):
            col = self.board_state[:, j]
            if 0 in col:
                available_cols.append(j)
        return available_cols

    # check if move is allowed, if so make the move
    def make_move(self, m, player):

        if m in self.get_allowed_moves():
            col = self.board_state[:, m]
            open_slot = np.argmax(col != 0) - 1
            self.board_state[open_slot, m] = self.players[player]

        # check if win draw loss or still playing 
        isWinDrawLoss = self.check_game_done(player)

        return self.board_state.copy(), isWinDrawLoss

    # given a list of numbers, check if there is 4 or more in a row of a certain type
    def checkHas4InARow(self, arr, player):

        current_val = arr[0]
        current_count = 1

        longest_val = arr[0]
        longest_count = 1

        for val in arr[1:]:

            if val == current_val:
                current_count += 1
            else:
                current_val = val
                current_count = 1

            if current_count > longest_count:
                longest_count = current_count
                longest_val = current_val

        if (longest_val == player) and (longest_count >= 4):
            return True

        return False

    # loop over all possible vertical, horizontal and diagonals and check if there 
    # are 4 in a row
    def check_game_done(self, player):

        # check if it is a draw first, as if it is a draw then there is no need to check for 4 in a row
        if np.sum(self.board_state == 0) == 0:
            self.gameOver = True
            return self.isWinDrawLoss['draw']

        # if not a draw, check if there is 4 in a row for the player
        # check if 4 consecutive 1s or 2s
        for i in range(self.width):
            col = self.board_state[:,i]
            has4 = self.checkHas4InARow(col, player)
            if has4:
                self.gameOver = True

        # now check the rows
        for i in range(self.height):
            row = self.board_state[i,:]
            has4 = self.checkHas4InARow(row, player)
            if has4:
                self.gameOver = True

        # now check the diagonals
        # Start with right diagonals, so start from the bottom left corner and move up to the right
        # The starting points are given by the x's shown below:
        #   - - - - - - -
        #   - - - - - - -
        #   - - - - - - -
        #   x x x - - - -
        #   x x x - - - -
        #   x x x - - - -
        for col_idx in range(0, 4):
            for row_idx in range(3, 6):
                right_diagonal = [self.board_state[row_idx - d, col_idx + d] for d in range(4)]
                has4 = self.checkHas4InARow(right_diagonal, player)
                if has4:
                    self.gameOver = True
        # Now do left diagonals
        # The starting points are given by the x's shown below:
        #   - - - - - - -
        #   - - - - - - -
        #   - - - - - - -
        #   - - - - x x x
        #   - - - - x x x
        #   - - - - x x x
        for col_idx in range(3, 7):
            for row_idx in range(3, 6):
                left_diagonal = [self.board_state[row_idx - d, col_idx - d] for d in range(4)]
                has4 = self.checkHas4InARow(left_diagonal, player)
                if has4:
                    self.gameOver = True

        if self.gameOver:
            return self.isWinDrawLoss['win']
        else:
            return 0.

    def reset(self):
        self.__init__()

The main responsibilities of the environment are:

Initialisation (__init__): This creates an empty board and stores metadata about the game such as the board dimensions and player identifiers.

Valid move detection (get_allowed_moves): This function returns a list of columns that still contain empty cells. The agent must choose actions from this set to avoid illegal moves.

Applying moves (make_move): When a player selects a column, the piece falls to the lowest available slot in that column. After placing the piece, the environment checks whether the game has ended and returns:

  • the updated board state
  • the reward associated with the move

Win detection (checkHas4InARow): This helper function checks whether a sequence contains four consecutive pieces from the same player. It is used internally when scanning rows, columns, and diagonals to detect wins.

Resetting the environment (reset): At the start of each training episode the board must be cleared. The reset function simply reinitialises the environment.

This environment class provides everything the reinforcement learning agent needs in order to interact with the game.

Representing Connect‑4 as an MDP

We can now describe the game as a Markov Decision Process.

State

The state is the board configuration:

\[s \in \{0,1,2\}^{6\times7}\]

This state contains all information needed to determine the next state.

Actions

The actions correspond to choosing a column:

\[a \in \{0,1,2,3,4,5,6\}\]

Invalid columns are filtered using get_allowed_moves().

Rewards

Rewards are returned when the game ends. The minimum number of turns to win/lose is 7, and the maximum number of moves is 42. We want a win in 7 moves to get the most points, 1, as this is the fewest number of moves, whilst a loss in 7 moves is the worst so this gets a reward of -1. So rewards lie between -1 and 1, with a draw being better than a loss and win being the best:

def reward_function(n_moves, outcome):
    if outcome == 'win':
        reward = 1 - (n_moves - 7) * (0.8 / (42 - 7))
    elif outcome == 'draw':
        reward = 0.2 - (n_moves - 7) * (0.4 / (42 - 7))
    elif outcome == 'lose':
        reward = -1 + (n_moves - 7) * (0.8 / (42 - 7))
    else:
        raise ValueError("Invalid outcome")

    return reward

With this, the reward is bounded between -1 and 1.

from collections import deque
import random
from dataclasses import dataclass

@dataclass
class Transition:
    state:      object   # e.g. np.ndarray (N,M)
    action:     int
    reward:     float
    next_state: object   # np.ndarray or None
    done:       bool

class ReplayBuffer:
    def __init__(self, capacity: int):
        self.memory = deque(maxlen=capacity)

    def add(self, tr: Transition):
        self.memory.append(tr)

    def sample(self, batch_size: int):
        return random.sample(self.memory, batch_size)

    def __len__(self):
        return len(self.memory)

replay_buffer = ReplayBuffer(100_000)

Random sampling breaks correlations between sequential game states and stabilises training.

class DeepQNetwork(nn.Module):
    def __init__(self, d_in: int, d_out: int, d_model: int, n_layers: int):
        super().__init__()

        self.layers = torch.nn.ModuleList()
        prev_dim = d_in
        for _ in range(n_layers):
            self.layers.append(nn.Sequential(
                nn.Linear(prev_dim, d_model),
                nn.GELU(),
            ))
            prev_dim = d_model


        self.out_layer = nn.Linear(prev_dim, d_out)

    def forward(self, x):
        # flatten x 
        B, N, M = x.shape
        x = x.view(B, N*M)
        for l in self.layers:
            x = l(x)
        x = self.out_layer(x)
        return x

A much more involved (and interesting!) model is given below called TransformerDQN, which we will use for the rest of the blog. This is based around the multiheaded attention mechanism, where the board is flattened and a relative position bias is added, and these are then passed through multiple transformer modules. In addition, the input is concatenated with a CLS token, and after the transformer layers the CLS token is passed through a feedforward network to give us our final output.

The reason for this model is that a connect-4 strategy depends heavily on spatial relationships across the board:

  • horizontal threats
  • vertical stacks
  • diagonal connections

Self-attention allows the network to compare distant board positions directly, which makes it easier to learn these patterns compared to a simple fully connected network.

    class TransformerDQN(nn.Module):
    """
    Connect-k policy network that selects a COLUMN action.

    Required inputs:
      board: LongTensor (B, N, M) with values {0,1,2}
        0 = empty, 1 = player1 piece, 2 = player2 piece

      player_to_move: LongTensor (B,) with values {0,1}
        0 = player1 to move, 1 = player2 to move

    Outputs:
      logits:        (B, M) raw logits over columns (unmasked)
      masked_logits: (B, M) logits with invalid columns set to -1e9 (safe for softmax/CE)
      valid_mask:    (B, M) boolean; True means column is playable (not full)
    """
    def __init__(
        self,
        d_model: int = 128,
        num_heads: int = 4,
        num_layers: int = 4,
        d_ff: int = 128,
        dropout: float = 0,
    ):
        super().__init__()
        self.n_rows = 6
        self.n_cols = 7
        self.seq_len = self.n_rows * self.n_cols
        self.d_model = d_model

        # Categorical embedding for cell states {0,1,2}
        self.cell_embed = nn.Embedding(3, d_model)

        # 2D learned positional embeddings (row + col)
        self.row_embed = nn.Embedding(self.n_rows, d_model)
        self.col_embed = nn.Embedding(self.n_cols, d_model)

        # CLS token is ALWAYS used
        self.cls = nn.Parameter(torch.zeros(1, 1, d_model))
        nn.init.normal_(self.cls, std=0.02)

        self.relpos_bias = RelativePositionBias2D(
            num_heads=num_heads,
            n_rows=self.n_rows,
            n_cols=self.n_cols,
            include_cls=True,
        )

        self.layers = nn.ModuleList(
            [TransformerEncoderLayer(d_model, num_heads, d_ff, dropout, relpos_bias=self.relpos_bias)
            for _ in range(num_layers)]
        )

        self.final_ln = nn.LayerNorm(d_model)
        self.dropout = nn.Dropout(dropout)

        # Policy head: one logit per column action (0..M-1)
        self.policy_head = nn.Linear(d_model, self.n_cols)

    @staticmethod
    def compute_valid_action_mask(board: torch.Tensor) -> torch.Tensor:
        """
        A column is valid if its TOP cell is empty (gravity connect-style).
        Assumes row index 0 is the TOP row, as in your examples.

        board: (B,N,M) values {0,1,2}
        returns: (B,M) bool
        """
        top_row = board[:, 0, :]  # (B,M)
        return top_row == 0

    def forward(
        self,
        board: torch.Tensor,
        valid_action_mask: Optional[torch.Tensor] = None,
        return_attn: bool = False,
    ):
        B, N, M = board.shape

        # get token embeddings
        x = self.cell_embed(board)

        # apply positional bias
        rows = torch.arange(self.n_rows, device=board.device).unsqueeze(1).expand(self.n_rows, self.n_cols)
        cols = torch.arange(self.n_cols, device=board.device).unsqueeze(0).expand(self.n_rows, self.n_cols)
        pos = self.row_embed(rows) + self.col_embed(cols)
        x = x + pos.unsqueeze(0)

        # flatten the board 
        x = x.view(B, self.seq_len, self.d_model)

        # append CLS token
        cls = self.cls.expand(B, -1, -1)
        x = torch.cat([cls, x], dim=1)
        x = self.dropout(x)

        # apply the encoder layers, save attention maps if you want to return them
        attn_maps = []  # list of (B,H,S,S) if return_attn
        for layer in self.layers:
            if return_attn:
                x, attn = layer(x, return_attn=True)
                attn_maps.append(attn)
            else:
                x = layer(x)
        
        # final layer norm
        x = self.final_ln(x)
        # extract the updated CLS token
        h = x[:, 0, :]
        # pass CLS token through policy network
        logits = self.policy_head(h)

        # apply the mask so only valid actions are returned. 
        # If a move isn't allowed, then replace its value with -1e9, so that 
        # after softmax this would become 0. 
        if valid_action_mask is None:
            valid_action_mask = self.compute_valid_action_mask(board)
        else:
            valid_action_mask = valid_action_mask.bool()

        masked_logits = logits.masked_fill(~valid_action_mask, -1e9)

        if return_attn:
            # attn_maps: length = num_layers, each (B,H,S,S) where S = 1 + N*M (CLS + cells)
            return logits, masked_logits, valid_action_mask, attn_maps

        return logits, masked_logits, valid_action_mask

class TransformerEncoderLayer(nn.Module):
    def __init__(self, d_model, num_heads, d_ff, dropout=0.1, relpos_bias=None):
        super().__init__()
        self.ln1 = nn.LayerNorm(d_model)
        self.ln2 = nn.LayerNorm(d_model)

        self.mha = MultiHeadAttention(d_model, num_heads, relpos_bias=relpos_bias)

        self.ffn = nn.Sequential(
            nn.Linear(d_model, d_ff),
            nn.GELU(),
            nn.Dropout(dropout),
            nn.Linear(d_ff, d_model),
        )
        self.dropout = nn.Dropout(dropout)

    def forward(self, x: torch.Tensor, attn_mask: Optional[torch.Tensor] = None, return_attn: bool = False):
        y = self.ln1(x)
        if return_attn:
            mha_out, attn = self.mha(y, y, y, attn_mask, return_attn=True)
            x = x + self.dropout(mha_out)
            x = x + self.dropout(self.ffn(self.ln2(x)))
            return x, attn

        x = x + self.dropout(self.mha(y, y, y, attn_mask))
        x = x + self.dropout(self.ffn(self.ln2(x)))
        return x

    class MultiHeadAttention(nn.Module):
    def __init__(self, d_model: int, num_heads: int, relpos_bias: nn.Module = None):
        super().__init__()
        assert d_model % num_heads == 0

        self.d_model = d_model
        self.num_heads = num_heads
        self.d_k = d_model // num_heads

        self.W_q = nn.Linear(d_model, d_model)
        self.W_k = nn.Linear(d_model, d_model)
        self.W_v = nn.Linear(d_model, d_model)
        self.W_o = nn.Linear(d_model, d_model)

        self.relpos_bias = relpos_bias  # may be None

    def scaled_dot_product_attention(self, Q, K, V, mask=None, return_attn: bool = False):
        attn_scores = torch.matmul(Q, K.transpose(-2, -1)) / math.sqrt(self.d_k)  # (B,H,S,S)

        # Add relative bias if provided (broadcast over batch)
        if self.relpos_bias is not None:
            attn_scores = attn_scores + self.relpos_bias()  # (1,H,S,S) -> broadcast to (B,H,S,S)

        if mask is not None:
            attn_scores = attn_scores.masked_fill(mask == 0, -1e9)

        attn_probs = torch.softmax(attn_scores, dim=-1)
        output = torch.matmul(attn_probs, V)

        if return_attn:
            return output, attn_probs
        return output

    def split_heads(self, x):
        batch_size, seq_length, _ = x.size()
        return x.view(batch_size, seq_length, self.num_heads, self.d_k).transpose(1, 2)

    def combine_heads(self, x):
        batch_size, _, seq_length, _ = x.size()
        return x.transpose(1, 2).contiguous().view(batch_size, seq_length, self.d_model)

    def forward(self, Q, K, V, mask=None, return_attn: bool = False):
        Q = self.split_heads(self.W_q(Q))
        K = self.split_heads(self.W_k(K))
        V = self.split_heads(self.W_v(V))

        if return_attn:
            attn_output, attn_probs = self.scaled_dot_product_attention(Q, K, V, mask, return_attn=True)
            output = self.W_o(self.combine_heads(attn_output))
            return output, attn_probs

        attn_output = self.scaled_dot_product_attention(Q, K, V, mask)
        output = self.W_o(self.combine_heads(attn_output))
        return output

    class RelativePositionBias2D(nn.Module):
    """
    Learned relative bias for a fixed 2D grid, added to attention logits.
    Produces bias of shape (1, H, S, S) where S = 1 + (R*C) includes CLS.
    """
    def __init__(self, num_heads: int, n_rows: int, n_cols: int, include_cls: bool = True):
        super().__init__()
        self.num_heads = num_heads
        self.n_rows = n_rows
        self.n_cols = n_cols
        self.include_cls = include_cls

        self.dr = 2 * (n_rows - 1) + 1  # 11 for rows=6
        self.dc = 2 * (n_cols - 1) + 1  # 13 for cols=7
        self.num_buckets = self.dr * self.dc  # 143

        # (H, num_buckets)
        self.bias_table = nn.Parameter(torch.zeros(num_heads, self.num_buckets))
        nn.init.normal_(self.bias_table, std=0.02)

        # Precompute pairwise bucket indices for the grid tokens (no CLS)
        coords = [(r, c) for r in range(n_rows) for c in range(n_cols)]
        coords = torch.tensor(coords, dtype=torch.long)  # (RC, 2)

        rel = coords[:, None, :] - coords[None, :, :]    # (RC, RC, 2) = (i-j)
        rel_r = rel[..., 0] + (n_rows - 1)               # shift to [0..dr-1]
        rel_c = rel[..., 1] + (n_cols - 1)               # shift to [0..dc-1]
        bucket = rel_r * self.dc + rel_c                 # (RC, RC) in [0..num_buckets-1]

        if include_cls:
            S = 1 + n_rows * n_cols
            full = torch.zeros(S, S, dtype=torch.long)
            full[1:, 1:] = bucket
            # CLS interactions: leave as 0 bucket (or make separate if you want)
            self.register_buffer("bucket_index", full, persistent=False)  # (S,S)
        else:
            self.register_buffer("bucket_index", bucket, persistent=False)  # (RC,RC)

    def forward(self):
        # bias_table: (H, B)
        # bucket_index: (S, S)
        # => (H, S, S)
        bias = self.bias_table[:, self.bucket_index]  # advanced indexing
        return bias.unsqueeze(0)  # (1, H, S, S)

def select_action(state, available_actions, steps_done=None, training=True):

    state = torch.tensor(state, dtype=torch.long).to(device).unsqueeze(dim=0)

    epsilon = random.random()
    if training:
        eps_threshold = EPS_END + (EPS_START - EPS_END) * math.exp(-1 * steps_done / EPS_DECAY)
    else:
        eps_threshold = 0

    # follow epsilon-greedy policy
    if epsilon > eps_threshold:
        with torch.no_grad():
            # action recommendations from policy net
            logits, masked_logits, valid_action_mask = policy_net(state) # (B,M), (B,M), (B,M)
            greedy_action = torch.argmax(masked_logits[0])
            return greedy_action.item()

    else:
        return random.choice(available_actions)

Q‑Learning Update

During training we update the network using the Q‑learning target

\[y = r + \gamma \max_{a'} Q(s',a').\]

The network is trained to minimise

\[(Q(s,a) - y)^2.\]

To minimise this we will use the Huber Loss, which acts like the normal mean squared error when the error is small (\(<1\)), and acts like the absolute error for larger errors. The reason for chosing this is to be less sensitive to large outliers. The optimisation is then performed with the normal Adam optimizer. Finally, the loss is minimised using a batch of transitions, with a batch size of 256.

BATCH_SIZE = 256
GAMMA = 0.999

optimizer = optim.Adam(policy_net.parameters())

def optimise_model():
    if len(replay_buffer) < BATCH_SIZE:
        return

    transitions = replay_buffer.sample(BATCH_SIZE)

    # first get all the states, actions, rewards, next_states in the batch of transitions
    # but we need to make sure that the final state has a Q value of 0, so we use masking
    state_batch = []
    action_batch = []
    reward_batch = []
    not_final_next_state_batch = []
    not_final_state_mask = []

    for tran in transitions:
        state_batch.append(tran.state)
        action_batch.append([tran.action])
        reward_batch.append(tran.reward)
        if tran.next_state is not None:
            not_final_next_state_batch.append(tran.next_state)
            not_final_state_mask.append(True)
        else:
            not_final_state_mask.append(False)

    state_batch = torch.tensor(np.array(state_batch), dtype=torch.long, device=device)
    action_batch = torch.tensor(np.array(action_batch), dtype=torch.long, device=device)
    reward_batch = torch.tensor(np.array(reward_batch), dtype=torch.float, device=device)
    not_final_next_state_batch = torch.tensor(np.array(not_final_next_state_batch), dtype=torch.long, device=device)
    not_final_state_mask = torch.tensor(not_final_state_mask, device=device)


    # prediction from policy_net
    logits, masked_logits, valid_action_mask = policy_net(state_batch)
    # get the logit corresponding to the action taken in the transition for each state in the batch
    state_action_values = masked_logits.gather(1, action_batch)

    # truth from target_net, initialize with zeros since terminal state value = 0
    next_state_values = torch.zeros(BATCH_SIZE, device=device)
    # tensor.detach() creates a tensor that shares storage with tensor that does not require grad
    target_logits, target_masked_logits, target_valid_action_mask = target_net(not_final_next_state_batch)
    next_state_values[not_final_state_mask] = target_masked_logits.max(1)[0].detach()
    # compute the expected Q values
    expected_state_action_values = (next_state_values * GAMMA) + reward_batch

    # Compute Huber loss
    loss = F.smooth_l1_loss(state_action_values, expected_state_action_values.unsqueeze(1)) # torch.tensor.unsqueeze returns a copy

    optimizer.zero_grad()
    loss.backward()
    optimizer.step()

from itertools import count
from tqdm import tqdm

num_episodes = 30_000
# control how lagged is target network by updating every n episodes
TARGET_UPDATE = 10

for i in tqdm(range(num_episodes)):

    # record model performance every 40 epochs
    if i % 40 == 39:
        win_rate, moves_taken = win_rate_test()
        training_history.append([i + 1, win_rate, moves_taken])
        th = np.array(training_history)

        # print training message every 200 epochs
        if i % 200 == 199:
            print('Episode {}: | win_rate: {} | moves_taken: {}'.format(i, th[-1, 1], th[-1, 2]))

    # start with a fresh board
    board.reset()
    state_p1 = board.board_state.copy()
    
    # loop over until the game is finished
    for t in count():
        # player 1 moves (our model)
        available_actions = board.get_allowed_moves()
        action_p1 = select_action(state_p1, available_actions, steps_done)
        steps_done += 1
        state_p1_, isWinDrawLoss_p1 = board.make_move(action_p1, 1)
        
        # check if player 1 has won, or if the previous move led to a draw
        if board.gameOver:
            if isWinDrawLoss_p1 == 1:
                # reward p1 for p1's win
                replay_buffer.add(Transition(state = state_p1, action = action_p1, reward = reward_function(t, 'win'), next_state = None, done = True))
            else:
                # state action value tuple for a draw
                replay_buffer.add(Transition(state = state_p1, action = action_p1, reward = reward_function(t, 'draw'), next_state = None, done = True))
            break

        # if the game is still going, player 2 to move
        available_actions = board.get_allowed_moves()
        action_p2 = random_agent(available_actions)
        state_p2_, isWinDrawLoss_p2 = board.make_move(action_p2, 2)
        
        # check if player 2 has won or if the move led to a draw
        if board.gameOver:
            if isWinDrawLoss_p2 == 1:
                # punish p1 for (random agent) p2's win
                replay_buffer.add(Transition(state = state_p1, action = action_p1, reward = reward_function(t, 'loss'), next_state = None, done = True))
            else:
                # state action value tuple for a draw
                replay_buffer.add(Transition(state = state_p1, action = action_p1, reward = reward_function(t, 'draw'), next_state = None, done = True))
            break

        # If neither won and no draw, then add transition to the buffer and go to player 1 move again
        replay_buffer.add(Transition(state = state_p1, action = action_p1, reward = 0, next_state = state_p2_, done = False))
        state_p1 = state_p2_

        # Perform one step of the optimization (on the policy network)
        # note that this will only actually run if there are enough transitions in the buffer
        optimise_model()

    # update the target network, copying all weights and biases in DQN
    if i % TARGET_UPDATE == TARGET_UPDATE - 1:
        target_net.load_state_dict(policy_net.state_dict())

Limitations and Extensions

Although Deep Q-Learning works well for relatively simple environments, it has limitations for adversarial board games.

Some challenges include:

  • instability due to bootstrapped targets
  • difficulty representing deep game trees
  • lack of explicit planning

Modern systems such as AlphaZero address these issues by combining:

  • neural networks
  • Monte Carlo Tree Search
  • self-play training

These techniques allow the agent to plan multiple moves ahead rather than relying purely on value estimation.

There are several directions this project could be extended:

Self-Play Training: Instead of a random opponent, train two agents against each other.

Double DQN: Reduces overestimation bias in Q-learning.

Monte Carlo Tree Search: Combining neural networks with search (as in AlphaZero) dramatically improves performance.

Curriculum Learning: Start with simpler opponents and gradually increase difficulty.

Summary

In this blog we first went over the core ideas of reinforcement learning before implementing a full Deep Q‑Learning pipeline for Connect‑4. This included:

  • A custom game environment
  • Experience replay to stabilise learning
  • A neural network approximating Q(s,a)
  • ε‑greedy exploration
  • A Q‑learning update rule

Even with a simple random opponent, the agent can learn useful strategies such as blocking opponent wins and forming connect‑4 patterns.
